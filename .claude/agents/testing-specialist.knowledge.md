# testing-specialist — accumulated knowledge

Read as Step 0 of every testing task; update when you discover a pattern,
find a helper, or are corrected. `testing-specialist.md` holds the durable
rules (DO-WRITE / DO-NOT-WRITE, production→test path map, Mock-vs-Fake).
This file holds **what was learned since**, as principles — never a log.

## How to update this file

- **PRINCIPLES only.** Fold new learning into the matching section as a 1-4
  line rule (merge with an existing bullet if it restates it). A principle
  earns its place only if a future run would act DIFFERENTLY — not "we once
  saw X." Append into the RIGHT SECTION, never onto the end.
- **Raw narrative goes to `testing-specialist.knowledge.archive.md`** under a
  new `## <date> — <title>` heading, then fold the one-line lesson in here.
  A dated "what happened today" entry never belongs in THIS file — that is
  what caused the 2026-07-24 rewrite (432K chars restating ~15 patterns).
- **Budget ~35,000 chars.** Past it, sharpen or retire a principle rather
  than growing the file.

## When to consult the archive

The archive is the full dated history, verbatim and chronological. Grep it
when a principle here is too terse to act on and you need the worked example
(test code, line numbers, failure output); when you hit an unfamiliar
mocktail stub mismatch, `MissingStubError` or fake-vs-real-Firestore
discrepancy not named below; when an emulator-lane setup fails (full
Windows/emulator runbooks live there); when you want a ticket's or area's
full review history (grep the BUT-#### or area name); or when a principle
cites "verified non-vacuous by X" and you want the revert-probe that proved
it, to reuse the technique.

## Principles

### Re-review economics (when asked to re-review "after automated fixes")
- **Confirm the tree actually MOVED before re-reviewing.** Cheapest proof: `ls --time-style=full-iso` the in-scope files against the mtime of the archive entry you last wrote — every file older than it means nothing landed (BUT-1691 round 3, and BUT-1661 rounds 2/3, all reviewed byte-identical trees). Say so up front, then spend the round on a probe the earlier rounds did NOT run rather than re-deriving their findings.
- The fix loop consumes Critical/High only, so a re-review whose findings are all Low/Medium returns unchanged forever. **Apply zero-risk TEST-ONLY fixes yourself** (fixture swaps, false comments, autopilot duplicates) and file only the production-behaviour items. Never edit production in a review pass — that needs a plan.
- Re-verify the archive's claims with a live probe rather than trusting them; a prior round's regex reasoning has been wrong before.
- **The tree can move DURING your round — a Critical is a claim until you re-read the file at the moment you file it.** 2026-07-28: `backfill-shared-list-contributors.ts:160` read `contributorUserIdsMUTANT` on two independent tool calls, then reverted to the correct name 12 minutes later (another session's revert-probe, mid-run). Re-`grep` the exact token and re-`ls --time-style=full-iso` before writing the finding; report a transient artifact as evidence that the SUITE could not see it, not as a live bug. Corollary: back up + `cmp`-restore your own probes in the same Bash call, because a parallel probe on the same file will otherwise be attributed to you.
- **READ THE MUTATED LINE BACK before believing a mutant's red count.** Patching a Dart file from a shell heredoc mangles backslashes silently: reverting `SwedishWordBoundary.boundedRegExp` to `'\\b(...)\\b'` wrote `'\b(...)\b'` — a literal U+0008, not a boundary — and the "reverting reddens exactly four" claim read as FALSE at 15 reds (2026-07-27). A mutant that reddens far MORE than the comment claims is the tell that you built the wrong mutant, not that the comment is wrong. `sed -n` the line, then re-run.

### FakeFirebaseFirestore vs emulator decision tree
| Behaviour under test | Use |
|---|---|
| Plain reads/writes/queries, `collectionGroup`+equality, `orderBy` on a present field | `FakeFirebaseFirestore()` in `setUp` |
| `FieldValue.increment`, `serverTimestamp` (usually), transactional writes, security rules | Emulator lane, or `firestore-rules-tester` |
| `GetOptions.source` (cache-first vs server) | NOT testable on the fake — ignores `source`, returns the same doc either way. Worse, real Firestore THROWS `FirebaseException(code:'unavailable')` on a `Source.cache` MISS; it does not return `exists:false`. So any `if (!cached.exists) throw NotFound` branch under a cache read is DEAD in production and its "passing" test is a fake artefact. Assert the outcome contract only. |
| `snapshot.metadata.isFromCache` (a "a cached read is NOT confirmation" guard) | NOT reachable on the fake — it answers EVERY read `isFromCache == false`, so each `if (...isFromCache) return null` line is dead across the whole suite and ships unasserted, even though it is usually the entire premise of the gate it lives in. `grep isFromCache <new suite>` → zero hits IS the finding, and it is the FIX's own new line, so a round-1 review cannot have caught it. Stage it by extending the file's sealed-class mock trick to `DocumentSnapshot`/`QuerySnapshot`/`SnapshotMetadata` (`when(() => snap.metadata).thenReturn(meta); when(() => meta.isFromCache).thenReturn(true)`) and give the mock a COMPLETE-looking payload, so only the flag separates it from a genuine server answer. Verified on BUT-1723's `confirmPersistedItemCount`, 2026-07-27: deleting both guards reddened only the two new tests (`Actual: <2>`, `Actual: <0>`). |
| A read of a doc that may NOT EXIST, in a rules-guarded collection | NOT testable on the fake, and the fake's answer is the OPPOSITE of production's. A rule that dereferences `resource.data` (e.g. `unified_shared_shopping_lists`, rules 1606-1609) DENIES a `get` on a missing doc, so the client gets `permission-denied` — never `exists:false`. Any "probe collection A, fall through to B when absent" helper therefore takes its CATCH branch on every B-shaped id in production. Check the catch falls THROUGH, not `return null`; `FirebaseShoppingRepository.read():264-277` is the in-repo template. Test it by injecting a `sharedListsRef` whose `.doc().get()` throws `FirebaseException(code:'permission-denied')` (sealed-class mock, as in the BUT-1696 cache-miss test) — and never pin the fake's fall-through answer as the contract (BUT-1723 did: a green test asserting `0` where production returns `null`). |
| Service that wraps Firestore | Mock at the repository interface |
- **`FakeFirebaseFirestore.runTransaction` is a NO-OP PASSTHROUGH — it can never prove atomicity.** Source (`fake_cloud_firestore_instance.dart:113` + `_DummyTransaction:210`): builds a dummy, calls the handler once, returns. `transaction.get` is a plain `docRef.get()`; `set/update/delete` write IMMEDIATELY and **drop `SetOptions`** (`merge:true` unverifiable); `timeout`/`maxAttempts` ignored; no isolation, abort or retry. Verified 2026-07-26: replacing `runTransaction` with a bare read-modify-write leaves such a suite 100% green (run that mutation before crediting any atomicity fix), and a truly interleaved two-writer test **FAILS on the fake while passing in production** — that case needs `firestoreForLane()` + `emulatorOnlySkip` (extend `test/integration/firebase/repositories/shopping_collaborative_mutation_integration_test.dart`). **Caveat: nothing in CI or `run_e2e_tests.sh` passes `--dart-define=USE_EMULATOR=true` over `test/integration`**, so every lane test is skipped everywhere — never coverage. **Re-proved end to end 2026-07-28 (BUT-1695/1730); do not re-derive, and do not accept a fix that just adds the flag.** `scripts/run_e2e_tests.sh` hardcodes `TEST_DIR="test/e2e"` (the `emulator` matrix leg of `e2e_tests.yml` runs only that), and `test.yml`'s `integration-tests` job boots the emulators but runs `flutter test test/integration` with NO define. Mock tier on the BUT-1665 two-writer proof prints `+0 ~1: All tests skipped.`; adding the define to the same command fails with `PlatformException(channel-error, ...FirebaseCoreHostApi.initializeCore)` because `flutter test` is a plugin-less Dart VM host. So the lane needs an `integration_test` host or a pure-Dart client — a project, not a flag. The right move for a review round is what the staged diff did: DOCUMENT it in the skip reason, the lane header and the CI step, and ticket it. Also declare the `firebase` tag in `dart_test.yaml`, or an undeclared tag warns on every run and files quietly drop it. A fake-backed transaction test DOES prove the handler's base came from a server read, not a client cache; keep it, just never label it a race test.
- `serverTimestamp()` inside `batch.set(..., SetOptions(merge:true))` does not reliably break the fake — only certain write shapes trip it; let a success test prove it lands.
- Fake CANNOT fire `permission-denied` — acceptable to skip only when the branch is a single `if (e.code=='permission-denied') return null;` above a rethrow with no side effects.
- A seeded fixture must include every field an `orderBy` reads — the fake (like real Firestore) silently drops docs missing it, which can masquerade as a query bug.

### Conscious-skip taxonomy (each discriminant is distinct)
- Static-method orchestrator: skip only when ALL hold — ≤3 calls, no injection seam, each in its own try/catch, no branching beyond the catches.
- Static disclosure whose sync contract is compiler-enforced (renamed `AnalyticsEvents.*`/l10n constant fails analyze/gen-l10n before any test runs).
- Pure-nav affordance (`pushNamed(<const route>)`) — route constant is compile-checked.
- Nth surface adopting an already-proven predicate: prove via `git diff --staged --name-only` — no new surface if the pure-logic file is absent from the diff.
- Mechanical `AppColors→theme` swap: skip only if finder-level assertions are unaffected.
- `SemanticsService.announce` in a fire-and-forget handler is skippable UNTIL the view gains a DI seam or full-shell harness — a conscious skip is dated, not permanent.
- A "sole guard"/"bypass not possible" comment is a claim until a test actually enters that exact branch.
- A comment-only diff owes no new test IF the claim is already pinned by a spy/Fake that would fail-loud if false — verify, don't trust.
- **A pure REMOVAL of dead code owes no new test when a repo-walking structural lint already holds the invariant — the lint IS the regression test, and an "absence of identifier X" test would be a strict subset of it plus hand-maintenance on every legitimate retirement.** Two things to verify before approving, both cheap (worked case: `has_algolia_search`, BUT-1500 follow-up, 2026-07-26): the lint file must be BYTE-IDENTICAL to HEAD (`git status --porcelain` + `git diff HEAD --` on it, both empty) — clearing a lint by weakening it looks the same in a green run as clearing it by fixing the code; and because such lints assert a SET is empty, confirm the pre-fix set had exactly ONE element, which proves the long-standing red wasn't masking a second violation behind the first.

- **A behaviour-NEUTRAL respelling (literal→escape, rename, reformat) owes no behavioural test — earn that verdict by MUTATION-COUNTING the existing suite, then fix the comment the respelling falsified.** Strip the load-bearing token from a replica and count reds before writing anything; the alarm usually already exists (BUT-1690: 3 of 6, as claimed). Check the reds against the file's other prefix/range/cascade SIBLINGS — an untouched one's alarm may live in a different suite. And re-read the suite HEADER: "fails if the bound regresses to `'x_'`" goes FALSE once the correct code also *renders* as `'x_'`, sending the next reader round the same loop. That comment fix is the deliverable, and it is test-only.

### Vacuity patterns — the recurring ways a "passing" test proves nothing
The single most repeated finding across two months of review. Check every new test against this list.
- **Circular determinism.** Calling the same pure function twice, or deriving the expected value from the SAME const the test guards, proves referential transparency, not the invariant. Pin the literal OUTPUT VALUE (`expect(buildId('r1','m1'), 'r1_m1')`, not `expect(buildId(...), buildId(...))`). Same trap for a cost/safety cap: if the expected length is computed FROM the const under test, add one literal pin (`expect(maxCompoundParts, 8)`).
- **Sibling-OR-branch short-circuit.** When the SUT is `if (A) return true; if (B) return true;`, every POSITIVE fixture must be built so only the branch under test can answer — otherwise the assertion is unfalsifiable. Enumerate the other branches and neutralise them in the fixture. Worked case (BUT-1691, fixed 2026-07-26): `IngredientLineDetector.looksLikeIngredient` also returns true for any line starting with a digit/fraction, so all five "unit matches as a whole word" / "case-insensitive unit" / recall-control fixtures were `'2 $unit mjölk'`-shaped and stayed green with the ENTIRE `_measurementPatterns` loop deleted. Swapping the lead to `'ca …'` made all five flip. The tell is cheap to spot: read the SUT's early-return list, then check whether any fixture satisfies a branch other than the named one.
- **Fake-default-same-as-expected.** If a Fake's optional-param default equals the "forwarded" value the test asserts, omitting the arg still passes. Use a sentinel default no real caller would pass (`maxDocuments = -1`).
- **Negative-scope claims need a negative assertion.** "Never includes email/phone" must assert ABSENCE (`toMap().keys` excludes it), not just presence of allowed fields.
- **Boundary tests must straddle the EXACT flip point.** For truncating `.inDays > N`, the flip is between `inDays==N` and `N+1` — a test at `N-1`/`N+2` misses tightening regressions entirely. Assert both `Duration(days:N,hours:12)` (not-yet) and `Duration(days:N+1)` (now).
- **"X does NOT happen" needs proof the code reached the point X could have.** Two different failure paths can share one negative observable (e.g. "strategy threw" vs "strategy not found" both yield empty events) — assert a signature UNIQUE to the intended path. **"No write was issued" is the commonest unfalsifiable instance:** comparing the doc's data before and after cannot tell "skipped the write" from "wrote identical values", so a `if (payload.isNotEmpty)` guard stays green when deleted (BUT-1719's `writes nothing when the entity matches the stored doc`). Count writes instead — `docRef.snapshots()` emissions, or a spy `DocumentReference`. **VERIFIED and closed 2026-07-28: the emission counter works on `FakeFirebaseFirestore` — an empty `update({})` still fires the listener, so dropping the guard reads `Actual: <2>` vs `<1>`.** Recipe: subscribe, `await pumpEventQueue()`, snapshot the count, act, `pumpEventQueue()` again, and put the positive control (one changed field → count rises) in the SAME test so a dead listener can't be what passes.
- **A hand-rolled test double that MODELS a write's effect instead of APPLYING its payload is blind to the payload's field NAMES — and a migration IS its field name.** BUT-1725's `runBackfill` suite ran 9/9 green against production writing `contributorUserIdsMUTANT`: the fake `batch.update(ref, data)` recorded `data` but then recomputed the store value via `reconstructContributors(...)` under a hardcoded `contributorUserIds` key, so every assertion read the effect the double wished for. Fix is two lines — union under `Object.keys(op.data)[0]`, plus one test asserting the key set equals the field the CONSUMER queries (here `probeResidualData`/`deleteShoppingLists`, `array-contains`). Verified 2026-07-28: renaming the field then reddens 3 of 10, where it previously reddened 0. Generalises to every in-memory double for `update`/`set`/`batch`: if the double never reads `data`'s keys, no test in that file can fail on a rename, a typo, or a wrong dotted path — and a one-shot migration failing that way still returns `success: true, hasMore: false`, which is the operator's signal to stop running it.
- **`findsNothing` needs a co-asserted positive render** in the same test, else a build crash upstream explains the absence too.
- **Two l10n keys with the SAME translated string in one widget make `find.text` unfalsifiable.** `displayUnknownUser` and `shoppingUnknownUser` are both "Okänd användare", and `ShoppingShareStatusDialog` renders one per member row with `userDisplayNames` defaulting to `const {}` — so `findsOneWidget` on the owner fallback passes with that fallback deleted (2026-07-27). Before asserting an l10n fallback, grep the ARB for other keys carrying the identical string and neutralise the siblings in the fixture (supply real names / drop to a personal-list fixture), or scope the finder. Asserting `context.l10n.<key>` captured from a `Builder` does NOT save you here — the collision is in the VALUE. **CLOSED 2026-07-28** — `test/widget/shopping/shopping_share_status_dialog_test.dart` is the first test to reference that dialog at all; the recipe is a 3-member fixture where only the target row is blank, `lastActivityAt: null` to keep the third source of the same string out, plus a recall control giving every row a real name. Two things NOT to assert there: the avatar's initial (whether an unresolved member shows "O" or "?" flipped mid-round and is a design call, not the guard), and any `isNotEmpty`-shaped spelling — assert the BEHAVIOUR (blank/whitespace → neutral label; empty stamp → the `Av:` row is absent while `När:` still renders) so a later consolidation into one `_knownNameOrNull` helper keeps it green.
- **"Returns null on permission denial" needs a positive control in the SAME fixture** — the null could come from an unrelated failure further down the same path.
- **Last-wins/correction tests must assert the LOSER is absent**, not just the winner present.
- **Precedence/weighting tests need inputs where the WRONG alternative gives a DIFFERENT number**, ideally opposite-direction (A: sig1=5,sig2=2; B: sig1=2,sig2=5 → assert weight(A)>weight(B)). Same-value inputs can't distinguish precedence from averaging.
- **A drift guard walking only `vocab → mapping exists` catches forward drift, not reverse** (a mapping the producer no longer emits still compiles). Fix: a POSITIVE test driving the real producer, asserting emitted set == vocabulary.
- **A partition/uniqueness test derived from the SAME curated list the impl was written from cannot fail.** For any `contains()`-based classifier, run a throwaway probe over every sibling name in the real vocabulary — surfaces substring-collision bugs in minutes. In an ORDERED first-match-wins rule chain, also probe for entries SHADOWED by an earlier rule: they are dead code that reads as coverage. **A shadow fix is per-ENTRY, not per-file — re-run the probe over the WHOLE chain after it.** The probe maps every rule literal → its own rule's category and prints mismatches; minutes to write, and the ONLY thing that catches this (BUT-1666 still leaves `tomatpuré` shadowed by veg `tomat` plus a dead duplicate line, twice). A golden-corpus diff adding only the exact inputs the fix targeted is this same vacuity — add one ADJACENT compound per rule touched, including rules the ticket never named (`jordnötssmör`→dairy via `contains('smör')`). **Then audit the corpus against the LITERAL strings the ACs name, one grep each:** BUT-1666 went green twice with 8 of 13 absent, two of those still wrong (closed 2026-07-26: corpus 17→37 cases). A regex guarded by ONE corpus case is minimal-but-non-vacuous; mutate it and count the reds. **When a probe shows the code disagrees with an AC, a passing-id-snapshot corpus gives a third option beyond "encode the code's answer" or "stop":** add the case with the CORRECT expectation and leave its id OUT of `_expectedPassing`. Set-equality still passes, the miss is reported in the nightly artifact's `failures[]`, and nobody can later read it as intended behaviour. Say so in the case notes and beside the omitted id.
- **A "does less work now" claim needs a discriminator test, not a convergence test** — seed something ONLY the naive path would wrongly pull in, assert it's absent.
- **A PARAMETERISED loop over failure codes/branches proves one leg N times when its fixture starts EMPTY.** The routing suite's `for (final code in ['unavailable','deadline-exceeded'])` was named "falls back to the cached base and returns the tick" but built on `_collabList()` (`items: []`) with an appending mutator, so both iterations took BUT-1683's `arrayUnion` fast path and `deadline-exceeded` had zero cached-base coverage; the append-onto-empty result is identical, so no assertion could tell. Fixed 2026-07-26 by seeding one row and ticking it, asserting the audit detail (`contains('cached-base')`) as the leg DISCRIMINATOR — then the standalone duplicate was deleted. Rule: when a fast path is selected by a property of the FIXTURE (length, emptiness, key presence), every parameterised loop over the slow path needs a fixture that fails the fast path's predicate, plus one assertion naming which leg ran.
- **A guard that classifies a mutation by comparing OLD vs NEW is untested whenever every fixture's base is EMPTY or the same LENGTH — the comparison loop never runs.** BUT-1683's `_appendedItems` (pure-append → offline `arrayUnion`, anything else → cached base) is the sole thing stopping an in-place edit from being queued as an `arrayUnion` that cannot express it, i.e. silent loss of the user's tick; all six offline fixtures build on `_collabList()` with `items: []`, so deleting the whole `DeepCollectionEquality` prefix loop stays green. The discriminating fixture is ONE mutator doing both (append `bröd` AND tick `mjölk` on a 1-item base) — verified 2026-07-26 to route to `cached-base` with the tick landing, so the guard is live and merely unasserted. Generalises: for any "only if X" fast path, the required test is the mixed case, not the pure one.
  **Same blindness one layer up, for an INDEX re-found after an `await`:** a rollback that re-finds its target by id instead of reusing a pre-await index is identically equal to the buggy version whenever the collection holds ONE element, and the "target vanished" arm is unreachable — `shopping_item_management_module_test.dart` has 36 fixtures and every one does a single `lists.add(...)` (2026-07-27). Count the fixture's COLLECTION length, not just its item list. The seam is already there and needs no `lib/` change: the SUT's injected `notifyListeners` callback fires after the optimistic mutation and BEFORE the await, so reorder/shrink the shared collection from inside that closure (which is exactly what the snapshot handler does — `_lists.removeWhere(isCollaborative)` + `addAll` on the same instance), then let the armed throw drive the catch. Assert the OTHER list is untouched, not just that the target was restored: a stale index writes one list's rows into another.
- **A predicate's SCOPE guard (single-word-only, suffix-not-substring, prefix-excluded) is the half that ships untested, because the fixture chosen to ILLUSTRATE it usually sits outside the predicate's vocabulary entirely.** BUT-1714's `isBareGlutenWord` whitespace guard ("multi-word labels like 'Till degen' stay headings") survived deletion across all 23 shipped fixtures — "Till degen" is not a gluten word under either version, so it cannot discriminate. The discriminating fixture must satisfy the predicate's POSITIVE half and fail ONLY on the guarded shape: "Ljust vetemjöl:" / "Till mjöl:". Same test for a suffix rule — only a compound carrying the word as a PREFIX ("Mjölblandning:") separates `endsWith` from `contains`. And when a rule deliberately over-captures (`endsWith('mjöl')` also catches gluten-FREE potatis-/majs-/mandelmjöl), pin the over-capture with a comment naming the safe DIRECTION, or a later tidy-up narrows it into the unsafe one.
- **Round-trips must drive the REAL serializer** (`toFirestore()`/`fromMap`), never `copyWith`. A model with two legs (`toJson`/`fromJson` cache AND `toFirestore`/`fromMap`) needs a non-null value asserted through BOTH independently.
- **A test title claiming something the fixture can't distinguish** ("SCALED line", "dest wins", "reverse drift caught by the compiler") — trace whether the fixture is at the default/identity config or the branch is unreachable. Audit names against bodies.
- **A test named as a round-trip that never calls the read-side function** is misleading and a coverage hole — grep test names against what bodies actually call.
- **A two-sided guard needs a discriminator PER SIDE, and a TIGHTENING needs a recall control.** Replacing ASCII `\b` with `(?<![a-zåäö0-9])tok(?![a-zåäö0-9])` fixes two independent halves; a natural corpus exercises only ONE, so deleting the other half leaves the suite green. **Classify each fixture by WHERE the å/ä/ö sits relative to the token and it sorts itself:** å/ä/ö BEFORE the token (`Kål`, `Mjöl`, `Höst`, `Råg`, `Rödkål:`) exercises ONLY the lookBEHIND; å/ä/ö AFTER it (`Gör så här`, `Lök:`, `Gäddan`) ONLY the lookAHEAD — all recorded live false positives. BUT-1691 first shipped trailing-side negatives only, and a lookbehind-only mutant kept the suite green. Also assert your negative fixture actually CONTAINS the token (`handduk` has no `dl`; use `medlem`). Never conflate a fixture's mutation value ("flips when I delete the lookbehind") with its regression value ("the OLD regex got this wrong") — a fixture has THREE histories: matched by old `\b` AND the fix (`råsocker` — `\b` DOES exist between `å` and an ASCII letter), matched by neither until now (`havssalt`, `vetemjöl`: pure new recall), or never matched (the negatives). Print each candidate pattern and run all three over every fixture before writing a word of rationale, and pair each negative with a positive control, because every tightening costs recall.
  **Which shape is correct is decided by the CONSUMER, not by tidiness — read the call site before rating a one-sided boundary as a bug.** This repo now holds both shapes, both right: `heuristics/ingredient_line_detector` is TWO-sided because its output is `likelyIngredientLines`, i.e. checkbox PRE-selection in the assisted wizard with the full `extractedText` retained (a false negative costs one tick), while `parsers/recipe_section_detector.looksLikeIngredient` stays TRAILING-ONLY because `text_import_strategy` has no fallback branch and a false negative DELETES an allergen-bearing line. Never "harmonise" them; the reasoning belongs in the group comment or the next session re-tightens it. When probing a two-sided lookaround, name each mutant by the fixture group it must flip and assert the WHOLE group (`expect(flipped, trailingEdge)`) — `isNotEmpty` masks a partial flip, and it is easy to pair the mutants backwards (deleting the lookBEHIND is what frees the TRAILING-side words). Measured BUT-1661/1691 word lists + per-fixture verdicts: archive, 2026-07-25 / 2026-07-26.
- **A HAND-BUILT narrow write payload (a map assembled key-by-key instead of the serializer's output) needs BOTH halves pinned — the keys it carries AND the keys it deliberately omits.** Worked case (BUT-1683 `_appendPayload`, closed 2026-07-26): `docRef.update({items: arrayUnion(...), ...activityKeys})` — deleting the whole activity-key loop stayed green because the only append test read `items` and the audit string, and `grep lastActivity` over the file returned nothing, so a replayed offline row would land under the PREVIOUS editor's name. Make the fixture's pre-existing stored value DIFFER from the expected one (`collaborative()` stamps `'alice'`, the mutator stamps `'bob'`) or the assertion can't fail; for the omission half, drive a mutator that moves an excluded key and assert it is unchanged — as the OWNER, so an escalation guard's early return cannot be what preserves it. Also walk every real mutator before rating a dropped non-item field as live: if all of them only touch the fields the payload carries, it is latent.

### Disposal & lifecycle guard idioms (BaseViewModel family)
- `BaseViewModel` already guards disposal TWICE (`clearError()` and `notifyListeners()`), so a subclass's OWN third guard is usually untestable-to-fail — `dispose()→clearError()→returnsNormally+notified==0` can't go red from removing it. Only test a disposal guard protecting an OBSERVABLE effect no base guard blocks (e.g. a late stream emission mutating a private field BEFORE the guarded notify — assert the STATE stays unchanged).
- Two quadrants when sweeping a guard across many VMs: (A) delegate disposed BY this VM's own `dispose()` — test `returnsNormally`+`notified==0`. (B) delegate is a SHARED SERVICE outliving the VM — `returnsNormally` is VACUOUS; assert the service's error SURVIVES the VM's disposal instead.
- A class with BOTH a local `_isDisposed` (set at the START of its own dispose) and inherited `BaseViewModel.isDisposed` (flips only inside `super.dispose()`, often LAST) must have any new guard use the SAME flag its own callbacks use. - A VM shadowing `error`/`hasError` must be proven by driving a FAILED base `executeAsync` (populates `super._error`) — seeding only a service-level error while base stays clean can't catch a dropped override. First check the VM calls base `executeAsync` at all; if error routing is fully manual, `super._error` is dead and this pattern doesn't apply.
- `executeAsync` RETHROWS on failure (not null). Prove it indirectly via a caller that only retries on THROW (assert attempt count) — a bare try/catch around the call is vacuous re: rethrow-vs-null.
- **A `dispose()` that clears DATA (not just controllers/timers) creates a use-after-dispose window for any long-running op still holding the object** — read the collaborator's dispose body before trusting "just a leak fix" (`FormFieldsManager.dispose()` also does `_values.clear()`). - **A "disposes its children" test asserting only `returnsNormally` on a still-callable method is vacuous.** Materialize the child (e.g. `state.manager.controllers`) BEFORE dispose, then assert it is dead: `expect(() => controllers.first.addListener(() {}), throwsFlutterError)` — `ChangeNotifier.addListener` debug-asserts not-disposed, so the assertion flips when the dispose line is reverted.

### Contract pinning: selectors, ordering, equality, revert
- Every `field == expected` selector needs THREE pins: matched-key reused, unmarked-collision untouched, marked-for-different-key untouched+new-created.
- `==`/`hashCode` tests need an equal pair (equal + same hashCode) AND a deliberately-unequal instance — equal-pair-only passes even if `==` regressed to `=>true`. - Ordering contracts need `verifyInOrder`, not call-count.
- A revert-to-start test must mutate first, THEN revert, then assert.
- Method removed+replaced: audit the deleted group with a test-by-test successor map — auth/permission branches are easiest to silently drop.
- `expect(() => asyncFn(), throwsA(...))` without `await` can pass spuriously — use `await expectLater(...)`.

### Settings-hydration & sentinel-parameter template (recurring: BUT-1220, 674, 1322, 1610)
Any field persisted via a private settings sub-doc needs: (1) a hydration test seeding the sub-doc DIRECTLY; (2) a corrupt-value test that ALSO asserts a SIBLING merged field survives (the merge is one `copyWith` in one try/catch — a naive parse of the corrupt field can abort the WHOLE merge, invisible if you only check the corrupt field's own null-safety); (3) a save-path test asserting the settings doc has it AND the public doc does NOT (privacy-leak guard) + round trip; (4) if the field has 3 serialization surfaces (Firestore/JSON-cache/copyWith), each needs its OWN test.
Sentinel-parameter contracts (`Object? field = _unset`) need both quadrants at the layer where omission is possible: omit→preserved, explicit-null→cleared. Prefer capturing the forwarded ARGUMENT IDENTITY against the sentinel (`identical(captured, Sentinel)`) over a downstream no-op — a regressed VM forwarding an in-memory null instead of the sentinel can coincidentally suppress the same effect.

### Firestore cost, index & cascade patterns
- A declared composite index needs its own assertion (the index array, in a test) — fakes can't catch a missing composite. Also assert `queryScope` (COLLECTION vs COLLECTION_GROUP) alongside field order.

### One-off gotchas, Windows/runner notes, and the revert-probe technique
- `Semantics(label:)` wrapping a tooltip'd button MERGES into one node with a concatenated label — match with `RegExp` (never exact String), bracket `bySemanticsLabel` with `tester.ensureSemantics()`/`handle.dispose()` in the SAME test.
- Optional-override params with an l10n `??` default: assert an injected override renders AND `find.textContaining(<default's unique substring>)` findsNothing — a shared substring makes the default-path test blind to whether the override threads through.
- A `GlobalKey` preventing State recreation is tested behaviorally: drive the state-changing event that WOULD recreate it, assert continuity survives — never assert on the key itself.
- **"Derives from a scaled/filtered list" claims need the list to provably DIFFER from its source** (factor ≠ 1.0) — testing at the default/identity config is structural blindness.
- A copy-SPLIT (two strings sharing a suffix) needs an assertion on the substring UNIQUE to each.
- Real `.xlsx` stores text via shared-strings (`t="s"`), not `inlineStr`.
- Age-boundary tests must pin the exact legal threshold on BOTH sides, not just far-side values.
- `export 'stub' if (dart.library.js_interop)` services: test only the stub's no-op contract; the web state machine is unreachable from VM tests.
- **When the test under scrutiny reads a FILE PATH rather than calling code (registry/structural lints, declared-index-config asserts), the mutant is a GIT REVISION — no `lib/` edit, no replica of production, nothing to restore.** `git show HEAD:<path> > scratch/`, then a throwaway replica of the *test's own* parse/walk parameterised on the path, run twice: control against the live file, mutant against the extracted revision. This is the cheapest probe in the ladder and the only one available when the "fix" is a deletion (there is no code left to mutate). Assert the mutant's exact expected set, not just non-emptiness — that is what distinguishes "the lint fires on this" from "the lint fires on something."
- **Revert-probe (the reliable non-vacuity proof):** copy the production file to scratch, string-replace the fix OUT, run the affected suite, confirm EXACTLY the expected test(s) go red at a unique assertion, restore and byte-verify with `cmp`. Construct the REAL object under the exact constructor wiring the bug lived in. Batch probes in one run only when each fails uniquely; separate when they share a code path. Back up IMMEDIATELY before editing — a parallel session may be editing the same file.
  **Three mechanics that make this survive a live parallel session (18 probes, 2026-07-28).** (a) Do the whole cycle — `cp` to `.bak`, mutate, run, restore from `.bak`, `cmp` — in ONE Bash call, and drive it from a tiny reusable script (`apply <file> <tag> <old.txt> <new.txt>` / `restore <file> <tag>`) that reads the OLD/NEW text from FILES; that is the only way a Dart snippet with backslashes survives the shell (a bash heredoc halved `\\s`→`\s` in the same session, and the Python `SyntaxWarning: invalid escape sequence` was the only tell). Assert the search text occurs exactly ONCE before writing. (b) On Windows, read/replace/WRITE IN BINARY. Python text mode silently rewrites CRLF→LF, so the md5 no longer matches the pristine file even though `git diff` still reads clean (autocrlf normalises) — a "restored" claim backed only by `git diff` is not byte-exact. (c) A mutated token that is MISSING at the end of the round is not automatically a failed restore: on this round `isBareGlutenHeadingCandidate` had been refactored away by the other session between the probe and the audit. Distinguish by `ls --time-style=full-iso` mtime + `git diff` of the region, never by assumption, and re-run the affected suites against the FINAL tree before reporting green.
- **When you are told not to touch `lib/` (or the plan-threshold gate refuses the edit), do NOT route around it.** Use a FAITHFUL REPLICA probe instead: copy the method body into a throwaway `test/zz_scratch_*_test.dart` (test files aren't gated) with the one line under probe swapped for a `Function` parameter, and open with a CONTROL test asserting the unmutated replica agrees with the real production function on every fixture — without that control the replica proves nothing. **This scales to a WHOLE CLASS** (used for BUT-1669/1667, 2026-07-26): `cp lib/X.dart test/.../zz_scratch_x_replica.dart`, rename only the class + its constructor, then `cp` the real suite beside it and sed the one import + the type name. Every `package:butlery/...` import resolves unchanged from `test/`, so the replica is byte-faithful; run the copied suite once UNMUTATED as the control (55/55 green proved the VM replica faithful), then mutate. It is blocked only when a mixin declares the type (`RecipeBackwardCompatibilityMixin` requires `RecipePersistenceManager get persistenceManager`, so a renamed replica can't be swapped in one layer down). Delete the scratch pair and re-grep the production file for the mutated token afterwards. Then run each mutant and print which fixtures flip. This also probes mutants the ticket didn't ask for (each HALF of a two-sided lookaround) in the same run, which a real file edit makes tedious. Delete the scratch files and `md5sum` the production files against the backups in the same call as the cleanup.
- **Cheapest probe of all when the SUT already injects the collaborator: mutate the INJECTION, not `lib/`.** If the bug is "the mutator built on X instead of Y", a throwaway harness that feeds the mutator X through the existing constructor seam reproduces the buggy output exactly, with the REAL production method bodies running. No lib/ edit, no replica, no control test needed (the bodies are genuine). Used 2026-07-26 to drive all six `ShoppingItemOperationsModule` collaborative tests red in one run. Applies whenever the differing value arrives as a constructor callback's argument.
- **A one-character change inside a string literal cannot be reviewed from `git diff` — `od -c` the BEFORE side, or you will invent the bug.** Live trap, `firebase_weekly_menu_plan_repository.dart` (2026-07-17, twice on 2026-07-26, and BUT-1690): the doc-ID prefix ranges read as `isLessThan: '${userId}_'` on BOTH sides of the diff — the classic empty range on a GDPR-export and a cascade-delete method — because HEAD already held a LITERAL U+F8FF (bytes `357 243 277`); the diff only escapes it. Behaviourally a no-op every time, so the finding is a FALSE one. Habits, in order: `od -c` / `git show HEAD:` any one-char literal diff before reasoning; **grep the ARCHIVE for the FILE NAME whenever a diff surprises you**; and never trust `grep uf8ff`, which measures NOTATION not semantics (it finds the sentinel only where escaped, reading as a one-of-N-siblings bug — the exact wrong conclusion). **The byte-form grep FALSE-NEGATIVES silently too**: `grep -P '\xef\xa3\xbf'` matches CHARACTERS under a UTF-8 locale and reported `functions/src` clean while `cat -A` showed the literal on a live GDPR-cascade bound; `LC_ALL=C grep -P` is refused outright here. Only three things work — the CODEPOINT form `grep -nP '\x{F8FF}'`, a Python sweep against `chr(0xF8FF)`, and `cat -A` (`M-oM-#M-?`). **And the char survives being TYPED as an escape into a tool call** — writing the six-char escape into Write/Edit/a heredoc produced the raw character twice in one session, which then broke a later `Edit`'s own `old_string`. Write `chr(0xF8FF)` / `U+F8FF` in prose only, then grep your own artefact.
- **Write throwaway probes with the Write tool, never a bash heredoc, and use RAW Dart strings (`r'\bfoo\b'`).** Backslashes silently die crossing the Bash layer even inside a quoted `<<'EOF'`: `RegExp('\\b$w\\b')` arrived as pattern `socker` with both boundaries GONE, so a probe reported "the old regex never matched" for every fixture and would have had me file a false finding against correct test comments. Always `print(re.pattern)` in a regex probe and eyeball it before trusting a single result.
- A `TimeoutException ... during "loading"` with 0 tests run is compile-bound (~12min shared `lib/` compile), not a hung test — split the invocation per-file to confirm.

### Firestore-rules `.ts` suites (emulator-gated)
- Every `&&` clause in an `allow` rule gets a failing test; every `cannotModify`/`hasRequiredFields` list needs a test PER FIELD.
- A failure-only update suite can be silently over-restrictive — pair denials with an `assertSucceeds` on a mutable field.
- The emulator persists docs ACROSS invocations — suffix create-test ids with a per-run `RUN = Date.now().toString(36)`, or a fixed-id create silently becomes an update on the 2nd run.
- These are hand-rolled `npx ts-node` runners against `127.0.0.1:8080` — time out without `firebase emulators:start --only firestore` running first.
