## Categories

1. **Generated / Data**: Auto-generated files — never modify, never count
2. **Complex Models**: Domain models with serialization, factory methods, operations
3. **Infrastructure Mixins**: Core utilities providing reusable patterns
4. **Repositories**: Tightly coupled to base classes
5. **Service Modules / Facades**: Already modular or well-organized
6. **Entry Points**: Must be self-contained
7. **Config / Constants / Data**: Intentionally centralized reference data
8. **Views / Widgets**: Cohesive single-screen implementations or already extracted

## When to Reconsider

Only refactor these files if:
- Adding significant new functionality that pushes them well beyond current size
- A clear extraction opportunity emerges (new reusable pattern identified)
- The file's role fundamentally changes

The 500-line guideline is a heuristic. These files remain larger because they represent cohesive functionality where splitting would add complexity without proportional benefit.
