## Categories

1. **Generated Code**: `app_database.g.dart` - never modify
2. **Infrastructure Mixins**: Core utilities providing reusable patterns. Splitting fragments cohesive functionality.
3. **Complex Models**: Domain models with serialization, factory methods, operations. Represent cohesive domain concepts.
4. **Repositories**: Tightly coupled to base classes. Extraction yields only 15-25% reduction while adding complexity.
5. **Service Modules**: Already well-organized modules within service facades. Further splitting creates unnecessary indirection.
6. **Entry Points**: `main.dart`, `main_e2e_optimized.dart` - must be self-contained.

## When to Reconsider

Only refactor these files if:
- Adding significant new functionality that pushes them well beyond current size
- A clear extraction opportunity emerges (new reusable pattern identified)
- The file's role fundamentally changes

The 500-line guideline is a heuristic. These files remain larger because they represent cohesive functionality where splitting would add complexity without proportional benefit.
