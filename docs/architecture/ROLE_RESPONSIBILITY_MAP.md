# Role Responsibility Map

A mapping of Butlery's codebase to the corporate roles that would own each concern
in a conventionally-staffed company. The point: a one-person operation (Malin directs,
Claude builds) covers all of these hats, and the role separation is legible in the
file structure — each concern has its own files, guard tests, and docs.

Generated by a multi-agent audit (18 role lenses). Treat as a living reference, not a
contract; update when ownership shifts.

---

## 1. Claude AI-Harness Owner / Agent-Ops Lead *(the "Claude setup")*

Owns the meta-tooling that lets Claude build this app autonomously — not an app
feature, but the machine that produces app features.

- **9-agent roster** with tiered triggers (Tier-2 commit-gated: code-reviewer,
  testing-specialist, firebase-backend-security, firestore-rules-tester).
- **Append-only `.knowledge.md` contract** — 5 agents accumulate dated lessons,
  Step-0 read, never delete.
- **21 enforcement hooks** — commit blocked until `.claude/state/*.marker` exist and
  aren't stale by mtime; PreCompact checkpointing; session-aware stop-analyze.
- **Auto-loaded `.claude/rules/`** + `accepted-deviations.md` so reviewers don't
  re-flag decided exceptions.
- **Model/effort policy** — `/code-review high` default, `xhigh` for
  repos/services/functions diffs.
- 16-skill catalog, lefthook integration, global self-improvement loop
  (`tasks/lessons.md`).

**Evidence:** `.claude/agents/*`, `.claude/hooks/` (require-review-before-commit.sh,
require-simplify-before-commit.sh, pre-compact.sh), `.claude/rules/`,
`.claude/plan-review-checklist.md`, `CLAUDE.md`, `tasks/lessons.md`, `lefthook.yml`

## 14. Database Administrator / Data Engineer

Owns the data layer as schema, not as features: **43 composite indexes** + 7 field
overrides, unified data model with `schemaVersion` lazy migration, **denormalization
& dual-write discipline** (BUT-458 comment-count backfill), **TTL/retention cleanup**
(8 cleanup functions — 90-day notifications, presence TTL), repository base/mixin
layer, daily snapshot rollups, RTDB presence, GDPR cascade/audit-log plumbing.

> Notable: **no dedicated `backup_service` and the Hive offline dir is empty
> (`.gitkeep` only)** — disaster recovery leans on Firestore's native backups, an
> under-owned seam.

**Evidence:** `firestore.indexes.json`, `functions/src/migrations/`,
`functions/src/cleanup/`, `lib/repositories/firebase/base_firebase_repository.dart`,
`database.rules.json`

## Genuinely un-owned (gaps)

- **ML / Data-Science Engineer** — the on-device ONNX/CRF parsing models + retraining
  scripts (`scripts/ner/`, `scripts/crf/`) have no owner for accuracy-drift
  monitoring or golden-dataset curation.
- **Subscription / Monetization Manager** — billing seeded to `free` for all beta
  users; explicit ownership deferred until paid launch.

## Worth noting

Butlery is run by a director-not-coder solo operation, yet the 18 hats are legible in
the file structure: each concern has its own files, guard tests, and docs. Two roles
are literally *executable* here — the Claude-Harness Owner (#1) is 9 agents + 21 hooks
+ a self-improving lessons log, and the Creative Director (#16) enforces brand
decisions with unit tests (a build fails if someone rounds a corner that brand says
must be square). The roles a normal company staffs with people, this project staffs
with rules, markers, and guard tests.
