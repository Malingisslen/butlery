# Role responsibilities map

_A reference that maps each aspect of **Butlery** to the **company role** that would own it in a
conventionally-staffed organisation — what a designer, controller, lawyer, security architect, etc.
would each be responsible for, **and** what each must watch in the outside world to stay current._

Butlery is built and directed solo (Malin directs in Swedish; Claude codes), so in practice one person
+ an agent wear all of these hats. The codebase is legible enough to **staff 28 notional roles**, each
with its own files, guard tests, budgets, runbooks — and now a **world-model**: the authoritative
external sources it must monitor, because an industry-grade app falls behind the moment its specialists
fall behind the frontier of their field.

Every responsibility is grounded in real files (paths are the source of truth; line numbers drift and
are omitted). Every world-model source URL was fetch-checked.

> Generated 2026-06-26 from a three-stage multi-agent sweep: a two-pass codebase audit (28 role lenses,
> audit → deepen/verify), a frontier-aware world-model layer (28 lenses, live web research), and a
> source-verification pass (151 URLs fetch-checked). Treat as a living reference, not a contract; refresh
> when major surfaces are added or removed.
>
> **Source caveat:** the build environment's egress proxy blocked several official domains (Apple,
> Google, W3C, EU, Flutter) with a 403 at fetch time. Those URLs are well-known canonical sources marked
> live-by-reputation, not byte-verified this run; re-confirm on an unblocked session. Two fabricated/stale
> URLs were caught and replaced; one hallucinated source was dropped.

## 1. Product Designer / UX

**Mandate.** Own the design system (lib/theme: 4A7C59 forest green, 8B5A3C rust, F8F4E8 cream tokens, Josefin Sans + Space Grotesk, BUT-695 square-corner language), component library fidelity (lib/widgets/styled, responsive patterns, 10 empty state variants with vegetable illustrations), and mockup compliance (docs/design).

Butlery's design system is exceptionally architected for a solo-directed app. Color palette: 4A7C59 forest green (primary), 8B5A3C rust (decorative only, never error), F8F4E8 cream (background), with 130+ semantic and component-specific tokens via Material 3 ColorScheme (light + dark with warm-brown overrides). Typography: Josefin Sans for headers (24px displaySmall down to 10px navLabel, with letter-spacing + platform-adaptive), Space Grotesk for body (17px–10px hierarchy, platform-adaptive). Spacing enforced via 4/8/16/24/32/48px scale (AppDimensions) with responsive multipliers (mobile/tablet/desktop). The UI state layer (StateWidget facade) covers 7 factory constructors: loading (peaAnimation branded loader default), empty (10 illustrated variants per BUT-986: broccoli/mushroom/pea pod/carrot, each tied to semantic l10n keys), error/success/info (via MessageStates), and skeleton loaders. All loading states use StateWidget, eliminating raw CircularProgressIndicator from views. Responsive behavior is built-in: LayoutContainers default 400px max-width, Breakpoints drive column counts (1/2/3 grids), card/dialog widths scale intelligently. StyledCard enforces BUT-695's square-corner language via assert: borderRadius=0.0 intentionally, making it impossible to accidentally add rounding to cards/buttons/badges/FABs.

## 2. Accessibility Specialist

**Mandate.** Owns WCAG 2.1 AA compliance across all platforms (iOS, Android, PWA): semantic labeling, tap-target sizing, contrast ratios, focus management, and screen-reader integration.

Butlery implements a mature accessibility framework anchored on WCAG 2.1 AA. minTouchTarget = 48.0 (AppDimensions) ensures Material Design compliance. Text-scale clamping at 1.4× (BUT-800, butlery_app.dart line 738) protects fixed-height layouts from overflow at extreme accessibility settings (200%+) while preserving readability gains. The project maintains 169 localized a11y labels in both Swedish and English ARBs, with Semantics wrapping pervasive across 145 widget files. Contrast is tracked and documented: textLight ≥6.2:1 on cream per WCAG 1.4.3 AA, greenMuted ≥4.6:1 on nav. Dialog focus return is contractual and tested in dialog_focus_return_test.dart across showDialog, showModalBottomSheet, and custom ConfirmationDialog. The tools/audit_unwrapped_tap_targets.dart scanner audits InkWell/GestureDetector for missing Semantics. However, external links in auth_view.dart (lines 546–560 Terms, 567–580 Privacy) and recipe_detail_shared_widgets.dart (lines 65–79 source URL) wrap InkWell/GestureDetector in Semantics(link: true) without the required label: field, violating WCAG 4.1.2 (Name, Role, Value)—screen readers cannot announce link purpose. This is the sole systemic gap.

## 4. Security Architect

**Mandate.** Design, validate, and monitor Butlery's defense-in-depth security posture across client auth, device integrity, server-side Firestore/Storage rules, and API protection.

Butlery implements a cohesive, multi-layer security stack. Server-side: Firestore rules (2,183 lines) enforce fine-grained ownership, allergen-critical field validation (CRIT-2 isValidTagResult, CRIT-8 _isValidUserIngredient), and rate-limiting (5–60s per action). Storage rules (114 lines) enforce per-user scoping with image-type whitelists (JPEG, PNG, WebP, HEIC, HEIF only; no SVG/BMP/TIFF). Device integrity via freeRASP (BUT-426, BUT-761) validates app tampering and root/jailbreak on mobile; Android uses production upload-keystore SHA-256 hash (1V4sCqD8sS+CuMNYsixjbTUz0FE7FOMULGCvw2n4380=) while iOS remains in debug mode pending enrollment. Session timeout (45min default, BUT-31) with 5min warning provides unattended-device protection. Account maturity gate (kAccountMaturityWindow = 60 minutes or email-verified) prevents fresh-account spam (BUT-659). Certificate pinning infrastructure (BUT-427, BUT-814) fully deployed but intentionally empty (no third-party pinning per OWASP guidance). App Check activation (ReCaptcha v3 web, Play Integrity Android, AppAttest+DeviceCheck iOS) enforces app origin on callables (marked "Unenforced" in console, per BUT-760 test harness). Permission validation (PermissionValidationMixin) gates all Firebase repository ops; Firestore rules remain authoritative. Secrets are environment-injected (String.fromEnvironment, --dart-define-from-file), never hardcoded.

## 10. Data / ML Engineer (parsing & tagging integrity)

**Mandate.** Own the **full recipe-data pipeline end to end** — from raw text to the allergen/dietary verdict the user trusts. ## How the world-model stays fresh

Each role's **World-watch** block is the seed of a horizon-scanning loop — the mechanism that keeps the
system current despite an LLM's fixed knowledge cutoff:

- **Cheap poll first.** Fetch each source's feed/changelog on its cadence; most cycles show no change.
- **Diff vs last snapshot.** Emit only deltas, never a re-summary — this is the cost lever.
- **Impact-check against the dossier.** A delta matters only if it touches our code or decisions.
- **Authority gates the action.** `flag-only` → surface in the morning brief; `auto-ticket` → file a
  Linear ticket (hard-deadline/ship-breaking roles); `escalate-human` → ask Malin (anything interpretive,
  i.e. all legal/privacy).
- **Cadence is volatility-matched:** weekly for high-churn surfaces (Apple/Play policy, CVEs, Claude Code
  releases), monthly for law/pricing/most tooling, quarterly for slow drift.

Sources with feed/`whats-new`/`release`/`archive` endpoints (89 of 151 URLs) are change-monitoring
surfaces; the rest are static references re-read on cadence.

## Worth noting

Butlery codifies role ownership through four interlocking mechanisms: (1) **file-structure legibility** — each role's concern owns a distinct directory (lib/theme/ for Designer, lib/services/llm/ for cost control, functions/src/account/ for GDPR erasure); (2) **executable enforcement via guard tests and markers** — the Creative Director / Brand Lead concern is literally enforced by a test that fails the build if someone rounds a square corner; commit gates gate on marker freshness (`.claude/state/<role>-done.marker`) stale-checked by mtime, requiring agent review before every commit touching the affected files; (3) **append-only decision records** (ACCEPTED_DEVIATIONS.md, lessons.md, knowledge.md files) that codify \"decided-no\" vs \"bug-not-yet-filed\", preventing re-litigation of settled calls; (4) **self-improving harness feedback loops** (agent roster with Tier-2 commit enforcement, knowledge files indexed by session date, lessons appended after corrections). The project does NOT staff roles with people — it staffs concerns with rules, markers, and agents. All 28 roles are named on the map; the real gaps are not absent roles but **named concerns with no enforcement mechanism or no operational owner in code** — e.g. tone governance, ML drift monitoring, doc staleness, and DR verification are each owned on paper but have no guard, CI gate, or alert binding the role to the actual artifact. Likewise, an overlap (like LLM cost control split across five named roles) has no built-in arbitration mechanism except user intent. The design is optimized for clarity over formality — each concern's file home is immediately searchable, and new rules are surfaced to agents at commit time — making role-boundary violations detectable within minutes, not sprint reviews; the residual risk is concerns that have a named owner but no executable guard, which stay invisible until something breaks.
